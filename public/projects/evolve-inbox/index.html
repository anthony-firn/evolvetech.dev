Evolve Inbox

A small inbox for mail sent to your own domain. Search messages, find attachments and check sender reports in the browser. Guided setup helps you deploy the same system yourself.

Try the fictional inbox →Source on GitHub ↗

Why I built it

EvolveTech needed an inbox for its own domain: a place to receive service messages and read them in a browser. A small receiving app was enough. Forward Email handles SMTP and posts parsed messages to a webhook; a Netlify Function stores them and serves the reader.

Try the reader

The public demo uses the same reader UI with three fictional messages. Search subjects, senders, recipients and previews, filter for attachments, open formatted mail or plain text, and inspect a failed sender check. It is read only and makes no requests to the real mailbox.

How mail arrives

A domain alias or catch-all points to a private webhook URL. Each delivery becomes a message object in site-wide Netlify Blobs storage, with a separate inbox index. The browser authenticates to the message API with the inbox password. The webhook has its own independent secret.

The forwarding rule is encrypted before it is published in DNS, keeping the webhook secret out of public TXT records. Provider accounts, deployment secrets and mailbox contents are not included in the repository.

What the reader does

  • Formatted HTML mail opens in a sandboxed frame with a policy that blocks scripts and remote images. A plain-text view remains available.
  • Attachments download directly from the authenticated message. SPF, DKIM and DMARC badges show the results reported by the forwarding provider.
  • Search matches the loaded message metadata, and an attachment filter helps find files. Failed requests show a retry path, and delayed responses cannot replace a newer message selection.
  • The layout adapts from a two-column desktop reader to a message list and reader on a phone. It follows the device's light or dark theme.

Run your own

Follow the setup guide → Run npm run setup to generate independent random secrets and private, domain-specific forwarding instructions. Import the settings into your own Netlify project, then configure a private alias or an encrypted DNS rule. The command refuses to overwrite existing credentials.

Run npm run doctor to check MX records, exposed TXT secrets, API authentication and deployed storage without sending test mail. Then send a real message from another account to verify the complete delivery path. Custom inbox names and domain guidance help make the deployment yours. Hosting and forwarding depend on the providers you choose.

Reliable delivery

Inbox index updates use conditional writes and bounded retries so simultaneous deliveries preserve each other's entries. Matching Message-IDs, recipients and content reuse the first stored copy, including its receipt time. If a save is interrupted after storing the body, a provider retry can repair the missing index entry.

Malformed payloads are rejected, and the full parsed JSON payload is limited to 5,000,000 bytes including attachments. Storage failures return HTTP 503 for provider retries. Messages without a Message-ID cannot be reliably deduplicated, and writes across message and index objects are not a transaction.

Scope and limits

This is a receiving inbox for one owner. Sending, SMTP submission, IMAP, POP3, multiple accounts and a second factor are not implemented. Messages are not end-to-end encrypted; the forwarding and hosting accounts can access them.

The index lists the newest 2,000 messages, with no automated retention. Tests cover authentication, simultaneous deliveries, retries, interrupted saves, malformed payloads, attachments and deletion. Browser checks exercise search, mobile layout, failed-request recovery, locking and isolation of untrusted HTML.
