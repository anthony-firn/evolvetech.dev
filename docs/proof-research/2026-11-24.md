# Scheduler mission source notes

The complete saved transcripts of the manifesto reaction, the Hoff reaction and Hoff's original were read
before finishing v2. The first implementation from Claude had used titles/descriptions; this revision uses
the transcripts. Local transcript copies live in the original Claude job scratch folder, not in the public site.

Prime's concrete example is a browser-agent/build scheduler. He describes studying Slurm and Kubernetes,
choosing local/global queues, and making program state visible. Hoff describes the changing application of
engineering experience and the loss some programmers feel. These views motivate the exercise; the game
retains implementation by hand and does not treat either video as an employment forecast.

Primary technical pages opened and read on 2026-11-24:

- Slurm scheduling configuration, Overview and Backfill Scheduling:
  https://slurm.schedmd.com/sched_config.html
  Slurm protects expected starts of higher-priority work using resource and runtime estimates.
- Slurm multifactor priority, formula and Age Factor:
  https://slurm.schedmd.com/priority_multifactor.html
  Age counts eligible waiting; dependencies do not accrue that waiting time.
- Kubernetes scheduler, Node selection:
  https://kubernetes.io/docs/concepts/scheduling-eviction/kube-scheduler/
  Filtering establishes feasibility, scoring ranks feasible candidates, binding records the choice.

The exercise deliberately differs: one machine, two integer resources, trusted bounded durations, an
unbounded submitted-time age score, deterministic ID ties and a single head reservation. Backfill is
conservative: it must finish by the reserved start even if unused capacity might permit a longer task.
It is not the full Slurm policy or a distributed execution service. Claims/leases, idempotence and handling
runtime overruns are explicit review topics and weekly extensions.
